2Сетевые модели: OSI и TCP/IP

Сетевая модель — способ описать, как данные передаются по сети. Разбивая процесс на уровни, проще разрабатывать протоколы, искать проблемы и учить специалистов.

2.1. Модель OSI — 7 уровней

OSI (Open Systems Interconnection) — эталонная модель ISO. 7 уровней, каждый решает свою задачу.

Сравнение моделей OSI и TCP/IP. Уровни OSI 5-7 соответствуют одному уровню TCP/IP.

2.2. Что делает каждый уровень OSI

№УровеньЗадачаПримеры протоколов
7ПрикладнойСервисы для пользователя: почта, веб, файлыHTTP, FTP, SMTP, DNS, SSH
6ПредставленияФормат данных: шифрование, сжатие, кодировкаTLS/SSL, JPEG, UTF-8
5СеансовыйУправление сессиями: открыть, поддерживать, закрытьRPC, NetBIOS
4ТранспортныйНадёжная доставка: TCP (с подтверждением) / UDP (без)TCP, UDP
3СетевойМаршрутизация: как пакет дойдёт через несколько сетейIP, ICMP, ARP
2КанальныйДоставка между двумя соседними устройствами в одной сетиEthernet, Wi-Fi, MAC
1ФизическийПередача битов по физической среде: кабель, радиоВитая пара, оптика

2.3. Инкапсуляция данных

Когда данные идут по сети, каждый уровень добавляет свой заголовок. Это называется инкапсуляцией.

Инкапсуляция: на каждом уровне данные «оборачиваются» в новый заголовок.

Обратный процесс на принимающей стороне — декапсуляция: снимаем заголовки по одному, пока не получим исходные данные.

2.5. Протоколы и их порты

Порт — числовой идентификатор приложения на устройстве. Позволяет одному серверу обслуживать разные сервисы одновременно.

ОбластьПример

Практические команды

$ ping 8.8.8.8           # проверка доступности (уровень 3)
$ tracert 8.8.8.8        # Windows: маршрут (уровень 3)
$ traceroute 8.8.8.8     # Linux/Mac: маршрут (уровень 3)
$ nslookup google.com    # DNS-резолвинг (уровень 7)
$ netstat -an            # Windows: активные соединения (уровень 4)
$ ss -tuln               # Linux: слушающие порты (уровень 4)
$ curl -I https://ya.ru  # HTTP-заголовки (уровень 7)
Проверка разных уровней модели OSI через утилиты командной строки.

Практическое задание

🎯 ПР №2 · Wireshark и уровни OSI 45 мин
Задача: увидеть реальный трафик и его уровни через Wireshark.
  1. Установите Wireshark (wireshark.org) — бесплатный анализатор трафика.
  2. Запустите Wireshark, выберите активный интерфейс (Wi-Fi или Ethernet).
  3. Начните захват, откройте в браузере любой сайт. Остановите захват.
  4. Найдите пакет с HTTP-запросом:
    • В фильтре введите http
    • Кликните на любой пакет
    • В нижней панели разверните уровни: Frame, Ethernet, IP, TCP, HTTP
  5. Запишите:
    • MAC-адреса отправителя и получателя (уровень 2)
    • IP-адреса (уровень 3)
    • Номера портов (уровень 4)
    • HTTP-метод и URL (уровень 7)
  6. Сохраните захваченный трафик в файл capture.pcapng.
Результат: скриншот развёрнутого пакета + файл pcapng + письменный отчёт.

Вопросы для самопроверки

Вопрос 1. Почему OSI 7 уровней, а TCP/IP — 4?
OSI — теоретическая модель, созданная ISO как эталон. Она детально описывает все возможные функции, разбивая их на 7 уровней.

TCP/IP — практическая модель, выросшая из реального стека протоколов ARPANET. Три верхних уровня OSI (5, 6, 7) на практике реализуются одним приложением, поэтому их объединили в один «Прикладной».

В реальности используется TCP/IP, но при обучении и диагностике ссылаются на OSI — она удобнее для понимания.
Вопрос 2. Что такое инкапсуляция?
Инкапсуляция — процесс добавления заголовков при движении данных вниз по стеку.

Пример: HTTP-запрос
1. Транспортный уровень добавляет TCP-заголовок (порт источника, порт назначения, номера последовательности).
2. Сетевой уровень добавляет IP-заголовок (IP-источник, IP-назначение, TTL).
3. Канальный уровень добавляет Ethernet-заголовок (MAC-источник, MAC-назначение).
4. Физический уровень преобразует всё в биты и отправляет по кабелю.

На приёмной стороне происходит обратный процесс — декапсуляция.
Вопрос 3. Почему DNS работает через UDP, а не TCP?
Скорость и объём. DNS-запросы маленькие (обычно < 512 байт) и их очень много. UDP-заголовок 8 байт vs TCP 20+ байт — экономия трафика.

Нет состояния. DNS не нужен трёхсторонний handshake — один запрос, один ответ.

Повторная отправка. Если потерялся — клиент просто отправит снова через таймаут.

Исключение: для больших DNS-ответов (например, DNSSEC или зон > 512 байт) используется TCP или расширение EDNS0. Также при передаче зон между серверами.
Вопрос 4. На каком уровне работает пинг?
Пинг использует ICMP — протокол сетевого уровня (3). ICMP — вспомогательный протокол для служебных сообщений: «хост недоступен», «время жизни истекло», «эхо-запрос» (ping), «эхо-ответ».

ICMP не использует порты — он не транспортный. Работает поверх IP напрямую.

Firewall часто блокируют ICMP — тогда ping не работает, но сайт доступен. Это нормально и часто делается в целях безопасности.
