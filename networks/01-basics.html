1Общие сведения о компьютерной сети

Компьютерная сеть — совокупность устройств (компьютеров, серверов, принтеров, телефонов), соединённых каналами связи для обмена данными и совместного использования ресурсов.

Зачем нужны сети
  • Обмен файлами — отправить документ коллеге
  • Совместное использование ресурсов — один принтер на офис
  • Централизованное хранение — файловый сервер
  • Коммуникация — почта, мессенджеры, видеозвонки
  • Веб-сервисы — сайты, приложения, облачные хранилища

1.2. Классификация по административной модели

Одноранговая сеть (Peer-to-Peer)

Все устройства равноправны. Каждое может быть и клиентом, и сервером.

  • Плюсы: просто настроить, не нужен выделенный сервер.
  • Минусы: плохо масштабируется, слабая безопасность.
  • Где: домашние сети 2-5 устройств, торренты.

Сеть на основе сервера

Есть выделенный сервер (или несколько), который управляет ресурсами.

  • Плюсы: централизованное управление, безопасность, резервное копирование.
  • Минусы: дороже, нужен администратор.
  • Где: офисы, предприятия, дата-центры.

1.3. Топологии

Три классические топологии: звезда (актуальна), кольцо (устарела), шина (устарела).

1.4. Методы доступа к среде передачи

Когда несколько устройств используют один канал (например, Wi-Fi), нужно правило, кто когда передаёт.

CSMA/CD (Carrier Sense Multiple Access with Collision Detection)

Используется в старом Ethernet (с общим кабелем). Алгоритм:

  1. Слушай — если канал свободен, начинай передачу.
  2. Слушай во время передачи — если слышишь чужой сигнал, значит коллизия.
  3. Стоп — прекрати передачу, отправь сигнал JAM.
  4. Случайная пауза — подожди случайное время.
  5. Повтори.

Проблема: чем больше устройств, тем больше коллизий.

CSMA/CA (Collision Avoidance)

Используется в Wi-Fi (802.11). Нельзя одновременно передавать и слушать (радио), поэтому избегаем коллизий:

  1. Слушай канал.
  2. Если свободен — подожди ещё немного (Inter-Frame Space).
  3. Отправь короткий пакет RTS (Request to Send).
  4. Точка доступа отвечает CTS (Clear to Send).
  5. Передавай данные.

Маркерные методы

По сети ходит «маркер» (token) — специальный пакет. Передавать данные может только тот, у кого маркер. Использовался в Token Ring и FDDI.

  • Плюс: нет коллизий, предсказуемая задержка.
  • Минус: если маркер потерялся — вся сеть ждёт.

1.5. Модель клиент-сервер

Большинство сетевых взаимодействий построено по модели «клиент — сервер»:

Клиент отправляет запрос, сервер обрабатывает и возвращает ответ.

Примеры:

  • Веб: браузер (клиент) → веб-сервер (Apache, Nginx) → HTML-страница.
  • Email: почтовый клиент (Outlook) → почтовый сервер (SMTP, IMAP).
  • Базы данных: приложение → сервер БД (PostgreSQL).

Вопросы для самопроверки

Вопрос 1. Чем LAN отличается от WAN?
LAN (Local Area Network) — локальная сеть в пределах одного здания или кампуса. Высокая скорость (1-10 Гбит/с), малые задержки, один владелец.

WAN (Wide Area Network) — глобальная сеть, соединяющая устройства на больших расстояниях. Более медленная (обычно до 1 Гбит/с), большие задержки, много владельцев (провайдеры).

Интернет — самая известная WAN. LAN обычно подключается к WAN через роутер провайдера.
Вопрос 2. Почему CSMA/CD устарел?
Три причины:
  1. Коммутаторы вытеснили хабы. В современном Ethernet каждое устройство подключено к отдельному порту коммутатора. Коллизий нет в принципе.
  2. Full-duplex. Устройства могут одновременно передавать и принимать.
  3. Скорости выросли. При 1 Гбит/с коллизии стали бы фатальны для производительности.
CSMA/CD остался в учебниках как историческая концепция. Реально работает только CSMA/CA — в Wi-Fi, где среда всё ещё общая.
Вопрос 3. Зачем нужна топология «звезда», если есть Mesh?
Mesh — отказоустойчив (много путей), но дорог и сложен. Нужен минимум N(N-1)/2 соединений для N устройств.

Звезда — просто и дёшево. Один коммутатор + N кабелей. Отказ одного узла не влияет на других.

Компромисс: в современных сетях используют звёздно-распределённую топологию — несколько коммутаторов соединены иерархически. Это даёт и надёжность, и простоту.
