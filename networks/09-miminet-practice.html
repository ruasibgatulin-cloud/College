🎯Практика в miminet.ru

miminet.ru — бесплатный онлайн-симулятор сетей. Позволяет собирать сети из хостов, коммутаторов, маршрутизаторов, настраивать IP-адреса, запускать ping, traceroute, curl и анализировать трафик.

Перед началом работы
  1. Зарегистрируйтесь на miminet.ru.
  2. Войдите в аккаунт.
  3. Создайте новый проект: Проекты → Создать.
  4. Интерфейс: слева — библиотека устройств, по центру — рабочее поле, справа — настройки выбранного элемента, снизу — консоль.

Как сдавать работы

  • Экспорт проекта: Файл → Сохранить как JSON. Прикрепите файл к отчёту.
  • Скриншоты: успешный ping, traceroute, настройки устройств.
  • Отчёт: файл Word с описанием шагов и скриншотами.

Основные элементы miminet

УстройствоИконкаДля чего
Host🖥Компьютер, конечное устройство
Switch🔀Коммутатор, соединяет устройства в одной сети
Router📡Маршрутизатор, соединяет разные сети
Server🗄Сервер (HTTP, DNS, DHCP)
Cloud☁️Внешняя сеть (интернет)

Практическая работа №1 · Пинг двух хостов

🎯 ПР №1 · Базовое соединение 20 мин
Цель: соединить два компьютера через коммутатор и добиться пинга.
Отрабатываемые навыки: работа с интерфейсом, соединение устройств, настройка IP, базовая диагностика.

Шаги

  1. Перетащите на рабочее поле:
    • 2 хоста (Host)
    • 1 коммутатор (Switch)
  2. Соедините кабелями:
    • Host1 → Switch (порт 1)
    • Host2 → Switch (порт 2)
  3. Кликните на Host1, в настройках задайте:
    • IP: 192.168.1.10
    • Маска: 255.255.255.0 или /24
  4. Аналогично Host2:
    • IP: 192.168.1.20
    • Маска: /24
  5. Запустите проект кнопкой ▶.
  6. Откройте терминал Host1 (клик на устройстве → Terminal).
  7. Выполните пинг:
$ ping 192.168.1.20
$ ping -c 5 192.168.1.20
-c 5 — отправить 5 пакетов и остановиться.
Ожидаемый результат: 
5 packets transmitted, 5 received, 0% packet loss
Все пакеты дошли, потерь нет.

  2. JSON-файл проекта
  3. Ответ на вопрос: что произойдёт, если задать Host2 IP 192.168.2.20? Почему ping не пройдёт?

Практическая работа №2 · Маршрутизация между двумя подсетями

🎯 ПР №2 · Маршрутизатор в действии 30 мин
Цель: соединить две подсети через маршрутизатор и добиться связи между ними.
Отрабатываемые навыки: настройка двух сетей, шлюзов, traceroute.

Схема

Host1, Host2 → Switch1 → Router → Switch2 → Host3, Host4

Шаги

  1. Разместите:
    • 4 хоста
    • 2 коммутатора
    • 1 маршрутизатор (Router)
  2. У маршрутизатора два интерфейса: eth0 и eth1.
    • eth0 → в Switch1
    • eth1 → в Switch2
  3. Настройте сеть A (левая):
    • Router eth0: 10.0.0.1/24
    • Host1: 10.0.0.10/24, шлюз 10.0.0.1
    • Host2: 10.0.0.11/24, шлюз 10.0.0.1
  4. Настройте сеть B (правая):
    • Router eth1: 10.0.1.1/24
    • Host3: 10.0.1.10/24, шлюз 10.0.1.1
    • Host4: 10.0.1.11/24, шлюз 10.0.1.1
  5. Убедитесь, что на роутере включена маршрутизация между интерфейсами: 
    # на роутере:
echo 1 > /proc/sys/net/ipv4/ip_forward
  6. Проверьте связь из Host1 (левой сети) до Host3 (правой):
$ ping 10.0.1.10
$ traceroute 10.0.1.10
traceroute покажет, что пакет идёт через роутер 10.0.0.1.
Ожидаемый результат:
  • Ping проходит без потерь.
  • Traceroute показывает 1 хоп (роутер 10.0.0.1).
Что сдать:
  1. Скриншот ping
  2. Скриншот traceroute с видимым роутером
  3. JSON проекта
  4. Ответ: почему Host1 не может пинговать Host3 без указания шлюза?

Практическая работа №3 · Статическая маршрутизация

🎯 ПР №3 · Маршруты вручную 40 мин
Цель: соединить две сети через два маршрутизатора, настроив статические маршруты.
Отрабатываемые навыки: добавление маршрутов, анализ таблицы маршрутизации.

Схема

LAN-A — R1 — (транзит) — R2 — LAN-B

Адресация

  • LAN-A: 192.168.1.0/24 (шлюз на R1: 192.168.1.1)
  • LAN-B: 192.168.2.0/24 (шлюз на R2: 192.168.2.1)
  • Транзитный линк R1↔R2: 192.168.100.0/30 (R1 = .1, R2 = .2)

Шаги

  1. Настройте IP-адреса на всех интерфейсах.
  2. Хост в LAN-A пингует свой шлюз (192.168.1.1) — должен работать.
  3. Хост в LAN-A пингует хост в LAN-B — не работает, потому что R1 не знает, куда отправлять пакеты для сети 192.168.2.0.
  4. Добавьте статический маршрут на R1: 
    # на R1:
ip route add 192.168.2.0/24 via 192.168.100.2

# проверить таблицу:
ip route show
  5. Добавьте обратный маршрут на R2: 
    # на R2:
ip route add 192.168.1.0/24 via 192.168.100.1
  6. Проверьте пинг между хостами разных сетей.
Ожидаемый результат: ping между любыми хостами LAN-A и LAN-B проходит.
Что сдать:
  1. Скриншот таблиц маршрутизации R1 и R2
  2. Скриншот ping между хостами
  3. JSON проекта
  4. Ответ: что произойдёт, если убрать обратный маршрут на R2? Почему ping не пройдёт в одну сторону?

Практическая работа №4 · DHCP-сервер

🎯 ПР №4 · Автоматическая раздача IP 40 мин
Цель: настроить DHCP-сервер, чтобы хосты получали IP автоматически.
Отрабатываемые навыки: настройка DHCP, работа с dhclient, проверка lease.

Схема

DHCP-сервер — Switch — 3 хоста-клиента

Шаги

  1. Разместите:
    • 1 сервер (Server)
    • 1 коммутатор
    • 3 хоста-клиента
  2. Настройте на сервере DHCP:
    • Диапазон: 192.168.10.100 – 192.168.10.200
    • Маска: /24
    • Шлюз: 192.168.10.1
    • DNS: 8.8.8.8
  3. На хостах-клиентах запустите клиент DHCP: 
    $ dhclient eth0
# или в некоторых системах:
# udhcpc -i eth0
  4. Проверьте, что хосты получили IP: 
    $ ip a
$ ip route
    Каждый хост должен получить адрес из диапазона .100–.200.
  5. Проверьте пинг между клиентами и до сервера.
Что сдать:
  1. Скриншоты ip a на всех 3 клиентах
  2. Скриншот успешного ping
  3. JSON проекта
  4. Ответ: почему клиент не может получить IP, если сервер выключен?

Практическая работа №5 · DNS и HTTP-сервер

🎯 ПР №5 · Веб-сервер и доменное имя 50 мин
Цель: поднять DNS и веб-сервер, обратиться к сайту по имени.
Отрабатываемые навыки: DNS-записи, HTTP-запросы, разрешение имён.

Шаги

  1. Разместите:
    • 1 клиент (Host)
    • 1 коммутатор
    • 1 сервер DNS
    • 1 HTTP-сервер
  2. Настройте IP в одной сети: 192.168.10.0/24
    • Client: 192.168.10.10
    • DNS: 192.168.10.20
    • HTTP: 192.168.10.30
  3. На DNS-сервере добавьте зону и A-запись:
    • mysite.local → 192.168.10.30
  4. На HTTP-сервере запустите веб-сервер (встроенный в miminet).
  5. На клиенте укажите DNS-сервер 192.168.10.20 в настройках.
  6. Проверьте резолвинг и HTTP-доступ:
$ nslookup mysite.local        # должен вернуть 192.168.10.30
$ curl http://mysite.local     # получить HTML
$ curl -I http://mysite.local  # только заголовки
Ожидаемый результат:
  • nslookup возвращает IP сервера.
  • curl получает HTML-страницу.
  • curl -I показывает HTTP-заголовки (200 OK).

  1. Скриншоты всех 3 команд
  2. JSON проекта
  3. Ответ: почему без указания DNS-сервера curl не работает по домену?

Практическая работа №6 · NAT и выход в интернет

🎯 ПР №6 · Выход через NAT 40 мин
Цель: настроить NAT, чтобы внутренние хосты выходили во внешнюю сеть через один публичный IP.
Отрабатываемые навыки: NAT, iptables, проверка внешнего IP.

Схема

LAN (192.168.1.0/24) — NAT-Router — Internet (Cloud)

Шаги

  1. Разместите:
    • 2 хоста в LAN
    • 1 коммутатор
    • 1 маршрутизатор (NAT)
    • 1 Cloud (внешняя сеть)
  2. Настройте LAN:
    • Host1: 192.168.1.10/24, шлюз 192.168.1.1
    • Host2: 192.168.1.11/24, шлюз 192.168.1.1
    • Router eth0 (LAN): 192.168.1.1/24
  3. Настройте WAN:
    • Router eth1 (WAN): 203.0.113.5/24
    • Cloud: подключён к eth1
  4. Включите NAT на роутере: 
    # на роутере:
echo 1 > /proc/sys/net/ipv4/ip_forward

iptables -t nat -A POSTROUTING -o eth1 -j MASQUERADE
    MASQUERADE — режим PAT: подменяет IP-источника на IP интерфейса eth1.
  5. Проверьте пинг из Host1 во внешнюю сеть: 
    $ ping 8.8.8.8
$ curl ifconfig.me
    curl ifconfig.me покажет ваш внешний IP — должен быть 203.0.113.5.
Что сдать:
  1. Скриншот ping 8.8.8.8
  2. Скриншот curl ifconfig.me (показывает внешний IP)
  3. JSON проекта
  4. Ответ: почему без NAT хост в LAN не может выйти в интернет?

Практическая работа №7 · Анализ трафика (Wireshark в miminet)

🎯 ПР №7 · Захват пакетов 40 мин
Цель: захватить трафик и увидеть структуру пакетов на разных уровнях OSI.
Отрабатываемые навыки: чтение pcap-файлов, понимание инкапсуляции.

Шаги

  1. Соберите простую сеть: 2 хоста + коммутатор (как в ПР №1).
  2. Запустите захват трафика на коммутаторе (в miminet есть режим capture).
  3. С хоста 1 отправьте несколько пакетов: 
    $ ping -c 5 192.168.1.20
$ arp -a
  4. Остановите захват и скачайте pcap-файл.
  5. Откройте в Wireshark (если есть) или проанализируйте во встроенном анализаторе miminet.
  6. Найдите:
    • ICMP Echo Request и Echo Reply
    • ARP-запрос (Who has 192.168.1.20?)
    • MAC-адреса отправителя и получателя
Что сдать:
  1. Скриншот захваченных пакетов
  2. Описание: какие уровни OSI видны в одном пакете ICMP?
  3. Ответ: зачем нужен ARP, если уже есть IP-адреса?

Практическая работа №8 · Сеть офиса (итоговый проект)

🎯 ПР №8 · Комплексный проект 90 мин
Цель: собрать полноценную сеть офиса с двумя отделами, интернетом и серверами.
Отрабатываемые навыки: всё вместе — VLAN-сегментация через подсети, маршрутизация, NAT, DNS, HTTP.

Требования

  • Отдел 1 (Разработчики): 4 компьютера, подсеть 192.168.10.0/24
  • Отдел 2 (Бухгалтерия): 3 компьютера, подсеть 192.168.20.0/24
  • Серверный сегмент: 2 сервера (DNS + HTTP), подсеть 192.168.100.0/24
  • Маршрутизатор соединяет все три подсети.
  • NAT-роутер даёт выход в интернет (Cloud).
  • DNS-сервер резолвит office.local → IP HTTP-сервера.
  • HTTP-сервер отдаёт тестовую страницу.

Задания

  1. Нарисуйте схему сети (на бумаге или в draw.io).
  2. Разместите все устройства в miminet.
  3. Настройте IP-адреса, шлюзы, маски.
  4. Настройте статическую маршрутизацию на роутере между тремя подсетями.
  5. Настройте NAT на пограничном роутере.
  6. Настройте DNS и HTTP на серверах.
  7. Проверьте:
    • Пинг между отделами — работает.
    • Пинг до интернета — работает через NAT.
    • DNS-резолвинг office.local — работает.
    • HTTP-доступ — работает.
Что сдать:
  1. Схема сети (рисунок)
  2. JSON проекта
  3. Скриншоты:
    • ping между отделами
    • ping 8.8.8.8 через NAT
    • nslookup office.local
    • curl http://office.local
  4. Таблица IP-адресов всех устройств
  5. Краткое описание (10-15 предложений): какие технологии применили и почему
Критерии оценки
  • Отлично — вся сеть работает, все проверки пройдены, оформлен отчёт.
  • Хорошо — работает большинство проверок, есть 1-2 ошибки.
  • Удовлетворительно — сеть собрана, но часть сервисов не работает.
  • Неудовлетворительно — сеть не функционирует или не сдана.
