7DNS, маршрутизация и NAT

IP-адреса неудобны для людей — никто не запомнит 142.250.150.100. Поэтому существует DNS. А чтобы пакеты находили путь через десятки сетей, работает маршрутизация. Чтобы сэкономить IPv4-адреса — NAT.

7.1. DNS — система доменных имён

DNS (Domain Name System) — «телефонная книга» интернета. Преобразует доменные имена в IP-адреса.

DNS превращает человекочитаемое имя в машинный IP-адрес.

Иерархия доменов

DNS — иерархическая система. Корневые серверы → домены верхнего уровня → домены второго уровня и т.д.

Как работает DNS-запрос

  1. Кэш браузера/ОС. Проверяется, был ли недавно этот домен.
  2. Локальный DNS-сервер (обычно роутер или провайдер).
  3. Корневой DNS — «не знаю, но .com обслуживает вот эти серверы».
  4. DNS .com — «google.com обслуживает вот тот сервер».
  5. DNS google.com — «google.com → 142.250.150.100».

Ответ кэшируется на каждом уровне — на время TTL (Time To Live).

Типы DNS-записей

ТипЧто делаетПример
AДомен → IPv4google.com → 142.250.150.100
AAAAДомен → IPv6google.com → 2a00:1450:4010::64
CNAMEПсевдоним доменаwww.example.com → example.com
MXПочтовый серверexample.com → mail.example.com
NSDNS-серверы доменаexample.com → ns1.example.com
TXTТекстовые данные (SPF, DKIM)v=spf1 include:_spf.google.com

Команды DNS

# Простой запрос
nslookup google.com
nslookup google.com 8.8.8.8   # через конкретный DNS

# Linux/Mac
dig google.com
dig google.com +short
dig google.com A
dig google.com MX

# Windows
nslookup -type=mx google.com

# Кэш DNS
ipconfig /displaydns    # Windows
ipconfig /flushdns      # очистить

# Linux
resolvectl statistics   # система с systemd

7.2. Маршрутизация

Маршрутизация — процесс выбора пути для пакета от отправителя к получателю через промежуточные сети.

Таблица маршрутизации

У каждого маршрутизатора есть таблица: «для сети X отправляй через интерфейс Y на адрес Z».

# Windows
route print

# Linux
ip route show

# Пример вывода Linux:
# default via 192.168.1.1 dev eth0
# 192.168.1.0/24 dev eth0 proto kernel scope link
# 10.0.0.0/24 via 192.168.1.10 dev eth0
Таблица маршрутизации — «карта дорог» для пакетов.

Статическая маршрутизация

Маршруты прописаны вручную администратором. Используется в небольших сетях.

# Linux
ip route add 10.0.0.0/24 via 192.168.1.10
ip route del 10.0.0.0/24

# Windows (от админа)
route add 10.0.0.0 mask 255.255.255.0 192.168.1.10
route delete 10.0.0.0
route print
Пример: «чтобы попасть в сеть 10.0.0.0/24, иди через 192.168.1.10».

Динамическая маршрутизация

Маршрутизаторы сами обмениваются информацией о путях и строят таблицу. Работает в больших сетях.

ПротоколТипПрименениеОсобенности
RIPDistance-vectorМалые сетиПростой, но медленный (макс 15 хопов)
OSPFLink-stateКрупные сети, офисыБыстрый, гибкий, открытый стандарт
EIGRPГибридныйТолько CiscoБыстрый, но проприетарный
BGPPath-vectorИнтернет, между ASОснова маршрутизации в интернете
Автономная система (AS)
AS — группа сетей под единым управлением (например, сеть крупного провайдера). Внутри AS работает OSPF, между AS — BGP. Интернет состоит из ~75 000 автономных систем.

7.3. NAT — преобразование адресов

NAT (Network Address Translation) — механизм, который подменяет приватные IP-адреса на публичные при выходе в интернет.

NAT подменяет приватный адрес на публичный при выходе в интернет.

Виды NAT

ТипКак работает
Static NATПостоянная связь: один приватный ↔ один публичный
Dynamic NATИз пула публичных адресов — по мере необходимости
PAT (Port Address Translation)Все внутренние адреса используют один публичный, различия по портам (используется дома)

Как работает PAT

Роутер ведёт таблицу: «какой внутренний IP:порт соответствует какому внешнему порту».

# Таблица NAT/PAT на роутере (Linux iptables)
iptables -t nat -L -n -v

# Пример записей:
# 192.168.1.10:5000  →  203.0.113.5:30001
# 192.168.1.11:5000  →  203.0.113.5:30002
# 192.168.1.12:5000  →  203.0.113.5:30003
Один публичный IP обслуживает сотни устройств, различая их по портам.

7.4. Где это применяется

ОбластьПример
Веб-сёрфингКаждый ввод URL вызывает 20-100 DNS-запросов — большинство закэшировано
Домашний интернетВсе устройства (телефон, ПК, ТВ) выходят в интернет через один публичный IP благодаря NAT
Корпоративные сетиOSPF внутри сети, BGP — с провайдерами
ОблакаAWS/Azure используют BGP для управления маршрутами между регионами
БалансировщикиL4/L7 балансировка через NAT для распределения нагрузки

Практические задания

🎯 ПР №9 · DNS-диагностика 40 мин
Задача: изучить работу DNS через командную строку.
  1. Выполните nslookup google.com — запишите IP.
  2. Выполните nslookup google.com 8.8.8.8 — через Google DNS.
  3. Через dig (Linux) или nslookup -type=mx (Windows) найдите MX-запись для yandex.ru.
  4. Найдите NS-записи для wikipedia.org.
  5. Ответьте:
    • Сколько DNS-серверов у google.com?
    • Какое доменное имя для почты у yandex.ru?
    • Что такое TTL и зачем он нужен?
🎯 ПР №10 · Маршрутизация в miminet 60 мин
Задача: настроить статическую маршрутизацию между двумя сетями через 2 маршрутизатора.
  1. Откройте miminet, создайте проект.
  2. Схема: LAN-A — R1 — (транзит) — R2 — LAN-B.
  3. Адресация:
    • LAN-A: 192.168.1.0/24
    • LAN-B: 192.168.2.0/24
    • Транзитный линк R1-R2: 192.168.100.0/30 (R1 = .1, R2 = .2)
  4. На R1 добавьте маршрут к сети 192.168.2.0/24 через 192.168.100.2.
  5. На R2 добавьте обратный маршрут через 192.168.100.1.
  6. Проверьте пинг между хостами разных сетей.
  7. Запустите traceroute — увидите путь через оба роутера.
Результат: успешный ping + traceroute + JSON проекта.
🎯 ПР №11 · NAT и выход в «интернет» 45 мин
Задача: настроить NAT и проверить доступ из LAN к внешнему серверу.
  1. Схема: LAN (192.168.1.0/24) — R (NAT) — внешний сервер (8.8.8.8).
  2. На R настройте:
    • Интерфейс LAN: 192.168.1.1
    • Интерфейс WAN: 203.0.113.5
  3. Включите NAT (PAT) на R для исходящих пакетов из LAN.
  4. Проверьте: с внутреннего хоста ping 8.8.8.8 — работает благодаря NAT.
  5. Проверьте внешний IP: зайдите на ifconfig.me или аналог — увидите 203.0.113.5, а не ваш внутренний.

Вопросы для самопроверки

Вопрос 1. Что произойдёт, если DNS-серверы упадут?
Сайты станут недоступны по имени, но будут работать по IP.

Если у вас в кэше уже есть google.com → 142.250.150.100, браузер ещё некоторое время сможет открыть сайт. Но новые домены не будут резолвиться.

Что перестанет работать:
  • Ввод URL в браузере (по домену).
  • Почтовые клиенты (MX-записи).
  • Обновления ОС (обращаются по доменам).
  • API-сервисы.
Примеры реальных сбоев: атаки на Dyn DNS (2016) обрушили Twitter, Netflix, Reddit на несколько часов. Отключение DNS провайдера — распространённая проблема.
Вопрос 2. Почему BGP — основа интернета?
BGP (Border Gateway Protocol) — единственный протокол, который связывает автономные системы (AS) между собой.

Каждый крупный провайдер — это AS со своим номером (например, Ростелеком — AS12389, Google — AS15169). Провайдеры объявляют друг другу: «наши сети такие-то, идите к нам через такой-то маршрут».

Масштаб: BGP-таблица в интернете содержит ~950 000 маршрутов. Каждый маршрутизатор границы (border router) хранит их все и выбирает лучший путь по метрикам.

Уязвимость: BGP не проверяет, действительно ли провайдер владеет анонсируемой сетью. Отсюда известные BGP-hijacking атаки — когда злоумышленник «уводит» трафик чужой сети на себя.
Вопрос 3. Почему NAT не идеален?
NAT спас интернет от нехватки IPv4, но у него есть проблемы:
  • Ломает end-to-end модель. Устройство за NAT не может принимать входящие соединения без port forwarding.
  • Осложняет P2P. Торренты, VoIP, онлайн-игры требуют обходных путей (STUN, TURN, UPnP).
  • Проблемы с некоторыми протоколами. FTP, SIP, H.323 встраивают IP в тело пакета — NAT их не понимает без специальных ALG.
  • Нагрузка на роутер. Держать таблицу из тысяч соединений — не бесплатно.
  • Проблемы для отладки. Не видно реальных IP клиентов в логах сервера.
Именно поэтому все переходят на IPv6, где NAT не нужен — у каждого устройства свой уникальный публичный адрес.
Вопрос 4. Чем статическая маршрутизация отличается от динамической?
СвойствоСтатическаяДинамическая
Кто настраиваетАдминистратор вручнуюПротоколы автоматически
Реакция на измененияНет — надо править вручнуюАвтоматически перестраивается
МасштабМалые сети (2-5 маршрутов)Крупные сети (сотни маршрутов)
Нагрузка на CPUНетЕсть (обмен служебным трафиком)
ПрименениеМалые офисы, домашние сети, точки-точкаКорпоративные сети, интернет
Правило: если маршрутов мало и они не меняются — статика. Иначе — динамика.
