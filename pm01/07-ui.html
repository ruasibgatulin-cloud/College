7Разработка пользовательского интерфейса

UI (User Interface) — то, что видит пользователь. UX (User Experience) — как он себя при этом чувствует. Хороший интерфейс незаметен: пользователь делает то, что хотел, и не думает о кнопках.

7.1. Основные принципы UX

  1. Понятность. Пользователь сразу понимает, что делать.
  2. Обратная связь. Каждое действие даёт видимый отклик (нажал — стало видно, что нажал).
  3. Предсказуемость. Кнопки в одном месте работают одинаково.
  4. Минимум усилий. Частые действия — в 1-2 клика.
  5. Прощение ошибок. Можно отменить, подтвердить, вернуться назад.
  6. Доступность. Работает и для людей с ограниченными возможностями.

7.2. Правила размещения элементов

Визуальная иерархия

Важное — крупнее, ярче, выше. Менее важное — на втором плане.

Правило «F-паттерна»

Пользователь читает страницу по F-образной траектории: сверху вниз, слева направо. Главное — в левом верхнем углу, самое важное действие — тоже там.

Типичный макет: важное — наверху и слева, главное действие — справа.

7.3. Работа с цветом

Цвет несёт смысл. Неправильный цвет запутает пользователя.

ЦветЗначениеГде использовать
СинийДоверие, профессионализмКорпоративные сайты, банки
ЗелёныйУспех, безопасностьКнопки «Подтвердить», «Оплатить»
КрасныйОпасность, ошибкаУдалить, отменить, alert
ЖёлтыйВнимание, предупреждениеWarning-сообщения
СерыйВторостепенноеОтключённые элементы, фон
ОранжевыйПризыв к действиюCTA-кнопки, акценты

Правила

  • Не более 3 основных цветов. Много цветов = визуальный шум.
  • Проверяйте контраст. Тёмный текст на светлом фоне. Соотношение — минимум 4.5:1 (WCAG).
  • Не используйте цвет как единственный признак. Красный = ошибка, но не только цвет — добавьте иконку и текст.
  • Учитывайте дальтонизм. 8% мужчин не различают красный и зелёный.
Базовая палитра для большинства интерфейсов.

7.4. Типографика

  • Не более 2 шрифтов. Один для заголовков, один для текста. Или один на всё.
  • Размер текста. Минимум 14 px (на десктопе), 16 px (на мобильном). Заголовки — в 1.5-2 раза крупнее.
  • Межстрочный интервал. 1.4-1.6 от размера шрифта. Слишком плотно — читать тяжело.
  • Длина строки. 50-75 символов. Длиннее — глаз устаёт.
  • Выравнивание. По левому краю — читается легче всего. По ширине — для больших текстов.

7.5. Отступы и сетка

Отступы — половина дизайна. Даже идеальный контент плохо выглядит без воздуха.

  • Базовая единица. Обычно 4 или 8 px. Все отступы кратны ей: 4, 8, 12, 16, 24, 32, 48...
  • Группировка. Связанные элементы — близко друг к другу. Разные группы — дальше.
  • Сетка. Для десктопа — 12 колонок с отступом 24 px.
Внутри группы — маленькие отступы, между группами — большие.

7.6. Кнопки и формы

Кнопки

  • Иерархия: одна главная (Primary) на экран. Остальные — вторичные.
  • Размер: минимум 44×44 px (для пальца).
  • Текст: глагол, действие. Не «ОК», а «Сохранить».
  • Расположение: слева направо в порядке чтения. Главная — справа или сверху.
Три уровня кнопок: главная (заливка), вторичная (обводка), третья (просто текст).

Формы

  • Label всегда виден. Placeholder не заменяет подпись — он исчезает при вводе.
  • Порядок полей. Логичный: имя → email → пароль.
  • Валидация. Сразу после ввода, с понятным сообщением об ошибке.
  • Автофокус. Курсор сразу в первом поле.
  • Enter. Отправляет форму (для однострочных).
<!-- Хорошая форма -->
<form>
  <div class="field">
    <label for="email">Email</label>
    <input type="email" id="email" required autofocus>
    <small class="hint">Мы пришлём подтверждение</small>
  </div>

  <div class="field">
    <label for="pwd">Пароль</label>
    <input type="password" id="pwd" required minlength="8">
    <small class="error" hidden>Минимум 8 символов</small>
  </div>

  <button type="submit">Зарегистрироваться</button>
</form>

7.7. Правила хорошего сообщения об ошибке

ПлохоХорошо
«Ошибка 404»«Страница не найдена. Возможно, она была удалена»
«Неверный ввод»«Пароль должен содержать минимум 8 символов»
«Ошибка валидации поля #3»«Проверьте формат email: нужен символ @»
«Что-то пошло не так»«Не удалось сохранить: нет соединения с сервером. Попробуйте ещё раз»

Правила:

  1. Что произошло. Понятным языком, без технических кодов.
  2. Почему. Причина, если известна.
  3. Что делать. Как исправить или куда обратиться.
  4. Без обвинений. Не «вы ввели неправильно», а «проверьте формат».

7.8. Доступность (Accessibility)

  • Контраст — не менее 4.5:1 для текста (WCAG AA).
  • Клавиатура — всё можно сделать без мыши (Tab, Enter, Esc).
  • Alt-текст для картинок — для скринридеров.
  • Фокус — видно, где сейчас курсор.
  • Размер кликабельной зоны — минимум 44×44 px.
  • Не полагайтесь только на цвет — используйте иконки и текст.

Вопросы для самопроверки

Вопрос 1. Чем UX отличается от UI?
UI (User Interface) — визуальная часть: кнопки, цвета, шрифты, расположение.

UX (User Experience) — весь опыт взаимодействия: насколько легко достичь цели, понятно ли, что делать, приятно ли пользоваться.

Пример: красивая кнопка «Купить» (UI) — но если она находится на 5 экранов вниз от описания товара (UX), пользователь не купит.

Профессионалы говорят: UX важнее UI. Некрасивый интерфейс может работать отлично. Красивый, но непонятный — провал.
Вопрос 2. Почему placeholder не заменяет label?
Четыре причины:
  1. Исчезает при вводе. Пользователь ввёл первую букву — подсказки уже нет. Если забыл, что вводить — придётся очищать поле.
  2. Низкий контраст. Placeholder обычно светло-серый. Плохо для людей со слабым зрением.
  3. Не для скринридеров. Программы чтения с экрана ориентируются на label.
  4. Путает при автозаполнении. Браузер подставил значение — а подсказка пропала, непонятно, что это за поле.
Правило: label над полем, placeholder — для примера формата (например, «ivan@example.com»).
Вопрос 3. Что такое контраст и почему это важно?
Контраст — соотношение яркости текста и фона. Измеряется коэффициентом от 1:1 до 21:1.

Стандарты WCAG:
  • AA — минимум 4.5:1 для обычного текста, 3:1 для крупного (18+ pt).
  • AAA — 7:1 и 4.5:1 соответственно.
Почему важно: слабое зрение, яркий солнечный свет, плохой монитор — текст становится нечитаемым. Хороший контраст помогает всем, а не только людям с инвалидностью.

Проверить можно бесплатно на webaim.org/resources/contrastchecker.
Вопрос 4. Как сообщить пользователю об ошибке правильно?
Три обязательных элемента:
  1. Что произошло. «Не удалось сохранить файл».
  2. Почему. «Нет свободного места на диске».
  3. Что делать. «Освободите 500 МБ или выберите другой диск».
Плохо: «Ошибка 0x80004005». Хорошо: «Не удалось установить программу. Проверьте интернет-соединение и попробуйте ещё раз».

Также:
  • Не обвиняйте пользователя («вы неправильно ввели»).
  • Не используйте технический жаргон (если вы не пишете для программистов).
  • Показывайте ошибку рядом с полем, где она возникла, а не в общем MessageBox.
  • Не блокируйте весь интерфейс ради сообщения об одной ошибке.
