11Объектно-ориентированное программирование на C++

C++ был одним из первых языков, где ООП стало основной парадигмой. Здесь классы — не надстройка, а основа языка. В C++ ООП работает с ручным управлением памятью и строгой типизацией.

11.1. Классы и объекты

#include <iostream>
#include <string>

class Student {
public:                    // доступ для всех
    std::string name;
    int age;
    double average;

    // Конструктор
    Student(std::string n, int a, double avg)
        : name(n), age(a), average(avg) { }

    // Метод
    void print() const {
        std::cout << name << ", " << age << " лет, средний балл " << average << std::endl;
    }

private:                   // доступ только внутри класса
    std::string internalId = "STU-001";
};

int main() {
    Student s("Ivan", 18, 4.5);
    s.print();
    return 0;
}

11.2. Спецификаторы доступа

СпецификаторДоступКогда использовать
publicВсемПубличный API класса
privateТолько внутри класса и его friend'овПоля, вспомогательные методы (по умолчанию в class)
protectedКласс + наследникиМетоды для переопределения
class vs struct
Разница только в дефолтном доступе:
  • class — по умолчанию private
  • struct — по умолчанию public
Все остальные возможности одинаковы. В C++ struct тоже может иметь конструкторы, методы, наследование. Традиция: struct — для маленьких DTO (данные), class — для полноценных объектов.

11.3. Конструкторы и деструкторы

class Buffer {
private:
    int* data;
    int size;
public:
    // Обычный конструктор
    Buffer(int n) : size(n) {
        data = new int[n];
        std::cout << "Выделено " << n << " элементов\n";
    }

    // Конструктор по умолчанию (делегирует)
    Buffer() : Buffer(10) { }

    // Конструктор копирования
    Buffer(const Buffer& other) : size(other.size) {
        data = new int[size];
        for (int i = 0; i < size; i++) data[i] = other.data[i];
    }

    // Деструктор — вызывается автоматически
    ~Buffer() {
        delete[] data;
        std::cout << "Память освобождена\n";
    }
};

Список инициализации

Всё, что после : перед телом конструктора, — список инициализации. Это правильный способ инициализации полей.

// ПЛОХО (присваивание в теле)
Student(std::string n) {
    name = n;  // сначала default-конструктор, потом присваивание
}

// ХОРОШО (список инициализации)
Student(std::string n) : name(n) { }
Список инициализации эффективнее: не создаётся временный объект.

11.4. Статические члены класса

class Counter {
private:
    static int totalCount;   // общий для всех объектов
    int id;
public:
    Counter() {
        id = ++totalCount;   // увеличивает общий счётчик
    }
    int getId() const { return id; }
    static int getTotal() { return totalCount; }
};

// Определение статической переменной (в .cpp файле)
int Counter::totalCount = 0;

// Использование
Counter a, b, c;
std::cout << Counter::getTotal();  // 3
std::cout << c.getId();           // 3

11.5. Указатель this

this — указатель на текущий объект. Используется, когда имя параметра совпадает с полем:

class Student {
    std::string name;
    int age;
public:
    Student(std::string name, int age) {
        this->name = name;  // this->name — поле класса
        this->age = age;    // age — параметр
    }

    // Возврат *this для цепочки методов
    Student& setName(std::string n) {
        this->name = n;
        return *this;
    }
};

// Цепочка
Student s("", 0);
s.setName("Ivan").setName("Ivanov");

11.6. Перегрузка операторов

C++ позволяет задать поведение операторов для своих классов.

class Vector2D {
public:
    double x, y;
    Vector2D(double x, double y) : x(x), y(y) { }

    // Сложение: v1 + v2
    Vector2D operator+(const Vector2D& other) const {
        return Vector2D(x + other.x, y + other.y);
    }

    // Умножение на число: v * 2
    Vector2D operator*(double k) const {
        return Vector2D(x * k, y * k);
    }

    // Сравнение: v1 == v2
    bool operator==(const Vector2D& other) const {
        return x == other.x && y == other.y;
    }

    // Вывод в поток: std::cout << v
    friend std::ostream& operator<<(std::ostream& os, const Vector2D& v) {
        os << "(" << v.x << ", " << v.y << ")";
        return os;
    }
};

Vector2D a(1, 2), b(3, 4);
Vector2D c = a + b;     // (4, 6)
Vector2D d = a * 2;     // (2, 4)
std::cout << c;         // (4, 6)

11.7. Шаблоны (templates)

Шаблон — обобщённый код, работающий с любым типом. Это C++-версия дженериков.

// Шаблонная функция
template <typename T>
T max(T a, T b) {
    return a > b ? a : b;
}

max(5, 10);          // T = int
max(3.14, 2.71);     // T = double
max(std::string("a"), std::string("b"));  // T = std::string

// Шаблонный класс
template <typename T>
class Box {
    T value;
public:
    Box(T v) : value(v) { }
    T getValue() const { return value; }
    void setValue(T v) { value = v; }
};

Box<int> ibox(42);
Box<std::string> sbox("Hello");

11.9. Наследование и полиморфизм

class Animal {
public:
    virtual void sound() const {     // virtual — для переопределения
        std::cout << "Some sound" << std::endl;
    }
    virtual ~Animal() { }            // ВАЖНО: виртуальный деструктор
};

class Dog : public Animal {
public:
    void sound() const override {    // override — проверка компилятором
        std::cout << "Woof!" << std::endl;
    }
};

class Cat : public Animal {
public:
    void sound() const override {
        std::cout << "Meow" << std::endl;
    }
};

// Полиморфизм
std::vector<std::unique_ptr<Animal>> zoo;
zoo.push_back(std::make_unique<Dog>());
zoo.push_back(std::make_unique<Cat>());

for (const auto& a : zoo) {
    a->sound();  // Woof, Meow — разное поведение
}

Виртуальные vs невиртуальные методы

ТипКогда вызываетсяЦена
НевиртуальныйПо типу переменной (статическая привязка)Быстро, прямой вызов
ВиртуальныйПо реальному типу объекта (динамическая привязка)Через vtable — чуть медленнее
Правило виртуального деструктора
Если у класса есть хотя бы один виртуальный метод — деструктор тоже должен быть виртуальным. Иначе при удалении через указатель базового класса деструктор наследника не вызовется → утечка ресурсов.

11.10. Обработка исключений

#include <stdexcept>

double divide(double a, double b) {
    if (b == 0) {
        throw std::invalid_argument("Деление на ноль");
    }
    return a / b;
}

try {
    double result = divide(10, 0);
    std::cout << result;
}
catch (const std::invalid_argument& e) {
    std::cerr << "Ошибка: " << e.what() << std::endl;
}
catch (const std::exception& e) {
    std::cerr << "Общая ошибка: " << e.what() << std::endl;
}

// Свои исключения
class MyException : public std::exception {
public:
    const char* what() const noexcept override {
        return "Моё исключение";
    }
};

11.11. Умные указатели (C++11+)

Решают проблему ручного управления памятью. Автоматически вызывают delete.

УказательВладельцевКогда использовать
unique_ptrОдинЕдинственный владелец ресурса
shared_ptrМного (счётчик ссылок)Ресурс делится между объектами
weak_ptrСлабый, без владенияРазорвать цикл shared_ptr
#include <memory>

// unique_ptr — единственный владелец
std::unique_ptr<Student> s = std::make_unique<Student>("Ivan", 18, 4.5);
s->print();

// Передача владения
std::unique_ptr<Student> s2 = std::move(s);
// s теперь nullptr, s2 владеет объектом

// shared_ptr — несколько владельцев
std::shared_ptr<Student> shared = std::make_shared<Student>("Bob", 19, 4.2);
std::shared_ptr<Student> shared2 = shared;  // счётчик = 2
shared.reset();                              // счётчик = 1
// Память освободится, когда счётчик = 0

// Утечка не возможна — деструктор вызовется автоматически
// При выходе из функции, при исключении, при любом сценарии
Современное правило
В C++11+ почти не используют сырые new/delete. Используйте:
  • std::make_unique<T>(args) — для одного владельца
  • std::make_shared<T>(args) — для нескольких
  • Контейнеры STL (vector, string, map) — сами управляют памятью
Это современный, безопасный и эффективный C++.

11.12. Лямбда-функции

// Простая лямбда
auto add = [](int a, int b) { return a + b; };
std::cout << add(2, 3);  // 5

// С захватом переменных
int factor = 10;
auto multiply = [factor](int x) { return x * factor; };
std::cout << multiply(5);  // 50

// Захват по ссылке
int counter = 0;
auto increment = [&counter]() { counter++; };
increment();
std::cout << counter;  // 1

// Захват всего
auto lambda = [=]() { return factor; };  // по значению
auto lambda2 = [&]() { return counter; }; // по ссылке

// Сортировка с лямбдой
std::vector<int> v = {3, 1, 4, 1, 5};
std::sort(v.begin(), v.end(), [](int a, int b) {
    return a > b;  // по убыванию
});

Вопросы для самопроверки

Вопрос 1. Зачем нужен виртуальный деструктор?
Представьте иерархию: Animal (базовый) и Dog (наследник, у которого есть поле std::string* favoriteToy с выделенной памятью).

Без виртуального деструктора: 
Animal* a = new Dog();
delete a;  // вызовется только ~Animal(), память favoriteToy утечёт!
С виртуальным: 
class Animal {
public:
    virtual ~Animal() { }  // гарантирует вызов ~Dog()
};
Правило: если класс имеет хотя бы один виртуальный метод — деструктор тоже виртуальный.
Вопрос 2. Чем unique_ptr лучше сырого указателя?
Автоматическое освобождение. unique_ptr вызывает delete при выходе из области видимости: 
{
    std::unique_ptr<Student> s = std::make_unique<Student>();
    // ...
}  // s автоматически вызывает delete
Безопасность при исключениях. Если брошено исключение — память всё равно освободится. 
void f() {
    Student* raw = new Student();
    mayThrow();  // если бросит — raw утечёт
    delete raw;
}

void g() {
    auto safe = std::make_unique<Student>();
    mayThrow();  // если бросит — safe освободит память
}
Нулевые накладные расходы. unique_ptr того же размера, что и сырой указатель.
Вопрос 3. Что такое RAII?
RAII (Resource Acquisition Is Initialization) — ключевая идиома C++:
  • Ресурс захватывается в конструкторе
  • Освобождается в деструкторе
  • Живёт ровно столько, сколько живёт объект
Примеры:
  • std::unique_ptr — управляет памятью
  • std::fstream — управляет файлом (закрывается в деструкторе)
  • std::lock_guard — управляет мьютексом (освобождает при выходе из блока)
RAII — основа безопасного C++: не нужно помнить о delete, close, unlock. Всё происходит автоматически.
