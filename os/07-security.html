7Диагностика и безопасность

7.1. Логи — основа диагностики

Лог — файл, куда ОС и программы записывают события: запуски, ошибки, подключения, предупреждения.

Где лежат логи в Linux

ПутьЧто там
/var/log/syslogОбщий системный лог (Debian/Ubuntu)
/var/log/messagesОбщий системный лог (RHEL/CentOS)
/var/log/auth.logАутентификация, sudo, SSH
/var/log/kern.logСообщения ядра
/var/log/dpkg.logУстановка/удаление пакетов
/var/log/nginx/Логи веб-сервера Nginx

Современные системы (systemd) собирают логи через journald — централизованное хранилище, которое можно читать через journalctl.

7.2. Команды работы с логами

$ journalctl -xe --since "1 hour ago"
Ошибки за час. -x — пояснения, -e — сразу к концу.
$ journalctl -u nginx.service --since today
Логи конкретного сервиса.
$ journalctl -p err -b
Только ошибки с момента последней загрузки.
$ tail -f /var/log/syslog
Следить за системным логом в реальном времени.
$ dmesg | tail -20
Последние сообщения ядра (ошибки USB, диска, драйверов).
$ grep "Failed password" /var/log/auth.log | tail -10
Неудачные попытки входа. Если их много — возможен подбор пароля.
$ last -n 20
Последние 20 входов в систему.
$ lastb -n 20
Неудачные попытки входа (нужны права root).

7.3. Управление сервисами (systemd)

В современных Linux сервисы управляются через systemd. Каждый сервис — файл .service в /etc/systemd/system/ или /lib/systemd/system/.

$ systemctl status nginx
Текущее состояние сервиса: запущен, остановлен, ошибки.
$ sudo systemctl start nginx    # запустить
$ sudo systemctl stop nginx     # остановить
$ sudo systemctl restart nginx  # перезапустить
$ sudo systemctl reload nginx   # перечитать конфиг без остановки
reload мягче, чем restart — не теряет соединения.
$ sudo systemctl enable nginx   # автозапуск при загрузке
$ sudo systemctl disable nginx  # отключить автозапуск
enable ≠ start. enable = «запустится при следующей загрузке». start = «запусти прямо сейчас».
$ systemctl list-units --type=service --state=running
Все активные сервисы.
$ systemctl list-unit-files --type=service | grep enabled
Какие сервисы включены в автозагрузку.

7.4. Пользователи и группы

$ cat /etc/passwd
Список пользователей. Формат: имя:x:UID:GID:комментарий:домашний_каталог:shell.
$ cat /etc/group
Список групп.
$ sudo useradd -m -s /bin/bash alice   # создать с домашней папкой
$ sudo passwd alice                     # задать пароль
$ sudo usermod -aG sudo alice           # добавить в группу sudo
$ sudo userdel -r alice                 # удалить вместе с домашней папкой
Полный цикл работы с пользователем.
$ who           # кто сейчас в системе
$ w             # кто и что делает
$ last -n 10    # история успешных входов
$ lastb -n 10   # история неудачных входов
Кто, когда и откуда входил.

7.5. Безопасность: базовые правила

Правило 1: не работать под root

Root может всё — включая rm -rf /. Работайте под обычным пользователем, а для конкретных команд используйте sudo.

Правило 2: сильные пароли + SSH-ключи

  • Пароль ≥ 12 символов, с цифрами и спецсимволами.
  • Для серверов — отключить вход по паролю, оставить только SSH-ключи.
  • Приватный ключ — права 600, никому не передавать.

Правило 3: обновлять систему

$ sudo apt update && sudo apt upgrade -y
$ sudo apt autoremove -y
Обновление системы — закрывает известные уязвимости.

Правило 4: firewall

$ sudo ufw status              # проверить
$ sudo ufw enable              # включить
$ sudo ufw allow 22/tcp        # SSH
$ sudo ufw allow 80/tcp        # HTTP
$ sudo ufw allow 443/tcp       # HTTPS
UFW — простой фаервол для Ubuntu/Debian.

Правило 5: не запускать неизвестные скрипты

Команда curl URL | bash — популярный способ установки, но и опасный. Скрипт может делать всё, что угодно. Лучше сначала скачать и посмотреть:

$ curl -O https://example.com/install.sh
$ less install.sh   # прочитать, что делает
$ bash install.sh   # запустить
Никогда не делайте curl URL | bash не глядя.

7.6. Резервное копирование

$ rsync -avz --delete /home/user/ /backup/user/          # локально
$ rsync -avz /home/user/ user@server:/backup/user/       # на удалённый сервер
rsync — умное копирование: переносит только изменения. Флаги: a — архив (права, время), v — verbose, z — сжатие, --delete — удалять в цели то, что удалено в источнике.
$ tar -czvf backup-$(date +%F).tar.gz /home/user/important/
Архив с датой в имени — удобно хранить историю.

Вопросы и задачи для самопроверки

Задача 1. В auth.log за час 500 записей «Failed password». Что делать?
Признаки brute-force атаки. Что предпринять:
  1. Проверить IP-адреса попыток: grep "Failed password" /var/log/auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn | head
  2. Установить fail2ban — он автоматически блокирует IP после N неудач.
  3. Отключить вход по паролю в SSH: в /etc/ssh/sshd_config установить PasswordAuthentication no.
  4. Перезапустить SSH: sudo systemctl restart sshd.
Задача 2. Как узнать, какие сервисы запустятся при следующей загрузке? 
$ systemctl list-unit-files --type=service | grep enabled
Или посмотреть цель загрузки: systemctl list-dependencies default.target.
Задача 3. Сервис nginx не стартует. Как найти причину? 
$ sudo systemctl status nginx                # общий статус и ошибка
$ sudo journalctl -u nginx -n 50 --no-pager   # последние 50 строк лога сервиса
$ sudo nginx -t                               # проверить конфиг nginx
Обычно причина — синтаксическая ошибка в конфиге или занятый порт.
Вопрос. Почему curl URL | bash опасен?
Вы запускаете произвольный код с интернета от своего имени (а если через sudo — от root).

Возможные проблемы:
  • Скрипт может установить вредоносное ПО.
  • Может удалить ваши файлы.
  • Может отправить данные на чужой сервер.
  • Даже если источник доверенный — что, если сайт взломан и скрипт подменён?
Правильный подход: скачать → прочитать → запустить.
Практическое задание на пару
  1. Посмотреть: journalctl -p err -b — какие ошибки были с момента загрузки?
  2. Найти в auth.log (или /var/log/secure) последние 5 неудачных попыток входа
  3. Проверить активные сервисы: systemctl list-units --state=running
  4. Создать тестового пользователя student_test с домашней папкой
  5. Добавить его в группу sudo
  6. Проверить через id student_test
  7. Удалить пользователя с домашней папкой
  8. Сделать резервную копию /etc/ в /tmp/etc-backup.tar.gz
