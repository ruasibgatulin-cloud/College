2Архитектура операционной системы

2.1. Составные части ОС

  • Ядро (kernel) — центральная часть, управляет ресурсами, работает в привилегированном режиме
  • Драйверы — «переводчики» между ядром и физическими устройствами
  • Оболочка (shell) — интерфейс с пользователем (bash, zsh, PowerShell, cmd)
  • Системные библиотеки — готовые функции для программ (libc, .NET BCL)
  • Утилиты — сервисные программы (архиваторы, файловые менеджеры, редакторы)

2.2. Режимы работы процессора

Современные процессоры поддерживают уровни привилегий (protection rings). На x86 их четыре, но используются в основном два:

Уровни привилегий процессора. Переход из ring 3 в ring 0 — через системные вызовы.

Когда приложению нужно что-то «привилегированное» (прочитать файл, отправить пакет), оно вызывает syscall. Процессор переключается в ring 0, ядро выполняет операцию, возвращает результат. В Linux это read(), write(), open(), fork(), socket().

2.3. Типы ядер

Монолитное ядро

  • Все службы (планировщик, ФС, драйверы, сеть) — в одном адресном пространстве.
  • Плюсы: быстро, мало переключений контекста.
  • Минусы: падение драйвера = крах системы.
  • Примеры: Linux, старые Unix.

Микроядро

  • В ядре — минимум: планировщик, IPC, управление памятью. Всё остальное — как процессы в user space.
  • Плюсы: надёжность (драйвер упал — перезапустили), модульность.
  • Минусы: медленнее — много переключений контекста и IPC.
  • Примеры: QNX, Minix, L4.

Гибридное ядро

  • Микроядерная структура + часть служб для скорости — обратно в ядро.
  • Примеры: Windows NT, macOS (XNU).

2.4. Модель клиент-сервер (микроядерная)

В микроядерной архитектуре части ОС работают как серверы, а пользовательские программы и другие компоненты выступают клиентами. Они общаются через межпроцессное взаимодействие (IPC).

Микроядерная модель клиент-сервер: службы ОС общаются через IPC.

2.5. Драйверы устройств

Драйвер — программа, которая знает, как именно общаться с конкретным устройством. Ядро не содержит код для каждого принтера или видеокарты — оно загружает драйвер.

Типы драйверов

  • Модули ядра (Linux) — загружаются в ring 0, lsmod, modprobe
  • Драйверы user-space — работают в ring 3, медленнее, но безопаснее
  • Встроенные в ядро — собраны при компиляции, всегда в RAM

Команды работы с модулями Linux

$ lsmod
Список загруженных модулей ядра.
$ modinfo e1000
Информация о конкретном модуле (например, драйвер сетевой карты Intel).
$ sudo modprobe -r e1000   # выгрузить
$ sudo modprobe e1000      # загрузить
Выгрузка/загрузка модуля ядра (осторожно — может отключить сеть!).

Вопросы для самопроверки

Вопрос 1. Почему приложение не может напрямую писать в видеопамять?
Потому что видеопамять и видеокарта — критичные ресурсы. Если бы любая программа могла писать туда напрямую:
  • Одно приложение могло бы «сломать» вывод другого.
  • Вредоносная программа могла бы перехватить экран.
  • Не было бы изоляции между приложениями.
Поэтому вывод идёт через драйвер видеокарты, работающий в ring 0. Приложение просит нарисовать — ядро решает, как это сделать.
Вопрос 2. Почему Linux выбрал монолитное ядро, хотя микроядро надёжнее?
Исторически и практически — скорость. Монолитное ядро работает быстрее, потому что:
  • Меньше переключений контекста (всё в одном адресном пространстве).
  • Прямые вызовы функций вместо IPC.
  • Проще оптимизировать критические пути.
При этом в Linux есть загружаемые модули (LKM) — это компромисс: можно добавлять/убирать драйверы на лету.
Вопрос 3. Что произойдёт, если из системы удалить драйвер сетевой карты?
Ядро не сможет общаться с сетевой картой. Последствия:
  • Интерфейс исчезнет из системы (ip a его не покажет).
  • Пропадёт сеть, интернет, доступ к удалённым ресурсам.
  • Если это сервер — потеряете SSH-доступ.
  • После перезагрузки — снова нужно ставить драйвер (если он не встроен в ядро).
Задание на пару
На Linux-машине:
  1. Посмотреть список загруженных модулей: lsmod | head -20
  2. Выбрать один модуль и узнать о нём через modinfo
  3. Найти в /sys/module/ соответствующий каталог
  4. Записать: назначение модуля, автор, версия, зависимости
