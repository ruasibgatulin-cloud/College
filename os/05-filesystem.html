5Файловая система и ввод-вывод информации

5.1. Что такое файловая система

Файловая система (ФС) — способ организации данных на носителе: как хранятся имена файлов, где лежат их данные, как учитываются права, как вести журнал изменений.

5.2. Сравнение основных ФС

ФСОСМакс. файлОсобенности
ext4Linux16 ТБЖурналируемая, стандарт де-факто
XFSLinux8 ЭБХороша для больших файлов и серверов
BtrfsLinux16 ЭБСнапшоты, сжатие, самовосстановление
NTFSWindows16 ЭБЖурналируемая, права, шифрование, сжатие
FAT32Все4 ГБПростая, но файлы ≤ 4 ГБ
exFATВсе16 ЭБДля флешек, без ограничения 4 ГБ
APFSmacOS8 ЭБОптимизирована для SSD, снапшоты
Что такое журналирование
ФС перед изменением записывает намерение в специальный журнал. Если питание отключится — при следующей загрузке ФС восстановит целостность, не потеряв данные. NTFS, ext4, XFS, Btrfs — журналируемые. FAT32 — нет.

5.3. Иерархия каталогов Linux (FHS)

5.4. Права доступа

У каждого файла есть владелец (user), группа (group) и остальные (other). Для каждой категории — три права:

БукваЧислоЧто значит для файлаЧто значит для каталога
r4Читать содержимоеПросматривать список файлов
w2Изменять файлСоздавать/удалять файлы
x1Запускать (если программа/скрипт)Заходить в каталог
Как читать права
rwxr-xr-x = 755
rwx = 4+2+1 = 7 — владелец может всё
r-x = 4+0+1 = 5 — группа может читать и заходить
r-x = 4+0+1 = 5 — остальные тоже

rw-r--r-- = 644 — стандартные права для файлов

Часто используемые значения

ЧислоЧто значитГде применяется
755rwxr-xr-xИсполняемые скрипты, каталоги
644rw-r--r--Обычные файлы
700rwx------Личные скрипты, приватные папки
600rw-------Файлы с паролями, ключи SSH
777rwxrwxrwxВсе могут всё (небезопасно!)
555r-xr-xr-xТолько чтение и выполнение

5.5. Команды работы с файлами

$ ls -la
Подробный список файлов с правами, владельцами, размерами (включая скрытые).
$ pwd
Показать текущий рабочий каталог.
$ cd /var/log
Перейти в каталог. cd ~ — домой, cd .. — на уровень выше, cd - — в предыдущий.
$ cp -r src/ dst/
Копировать рекурсивно (-r — для каталогов).
$ mv old.txt new.txt      # переименовать
$ mv file.txt /tmp/       # переместить
Перемещение / переименование.
$ rm file.txt         # удалить файл
$ rm -rf dir/         # удалить каталог рекурсивно (ОСТОРОЖНО!)
Файл после rm не попадает в «корзину». Восстановить сложно.
$ mkdir -p a/b/c
Создать каталоги рекурсивно (-p — вместе с родителями).
$ cat /etc/hostname       # весь файл на экран
$ less /var/log/syslog    # постраничный просмотр (q — выход)
$ head -20 file.txt       # первые 20 строк
$ tail -f /var/log/syslog # следить в реальном времени
Просмотр файлов.

5.6. Управление правами

$ chmod 755 script.sh    # числовая нотация
$ chmod 644 file.txt
$ chmod u+x script.sh    # символическая: u=user, g=group, o=other
$ chmod -R 755 dir/      # рекурсивно
Изменение прав доступа.
$ chown alice:users file.txt
$ chown -R alice:users /home/alice/projects
Смена владельца (alice) и группы (users).
$ groups        # группы текущего пользователя
$ id alice      # UID, GID и группы alice
$ whoami        # текущий пользователь
Информация о пользователях и группах.

5.7. Дисковое пространство

$ df -h
Свободное место на всех смонтированных ФС.
$ du -sh * | sort -h
Размеры файлов и папок в текущей директории, по возрастанию.
$ du -sh /home/* 2>/dev/null | sort -h
Кто сколько занимает в /home.
$ find / -type f -size +100M 2>/dev/null
Найти все файлы больше 100 МБ.

5.8. Монтирование

$ lsblk              # список блочных устройств
$ mount | grep /dev/sd # что смонтировано
$ findmnt /           # какая ФС на корне
Просмотр дисков и точек монтирования.
$ sudo mount /dev/sdb1 /mnt    # смонтировать
$ sudo umount /mnt              # размонтировать
Ручное монтирование/размонтирование.

Вопросы и задачи для самопроверки

Задача 1. Дать скрипту права на выполнение только владельцу.
chmod 700 script.sh или chmod u+x script.sh.
700 = rwx------ — владелец может читать, писать, запускать. Остальные ничего не могут.
Задача 2. Почему SSH-ключ должен иметь права 600?
SSH-сервер отказывается использовать приватный ключ, если у него есть доступ у группы или остальных.

Права 600 = rw------- — только владелец читает и пишет. Если ключ увидят другие — злоумышленник может выдать себя за вас.

Проверить: chmod 600 ~/.ssh/id_rsa.
Задача 3. Файл занял 5 ГБ места. Как найти и удалить его? 
$ du -h / 2>/dev/null | sort -h | tail -20
$ find / -type f -size +1G 2>/dev/null
$ rm большой_файл
Вопрос. Чем отличается жёсткая ссылка (hard link) от символической (symlink)?
Hard link — ещё одно имя для того же inode. Оба имени ссылаются на одни данные. Удаление одного — данные остаются в другом.

Symlink — отдельный файл, который содержит путь к другому файлу. Если оригинал удалить — symlink станет «битым».

$ ln file.txt hardlink.txt       # hard link
$ ln -s file.txt symlink.txt     # symlink
Задание на пару
  1. Создать каталог ~/practice с подкаталогом sub
  2. Создать файл ~/practice/file.txt с текстом «Hello, OS!»
  3. Проверить права: ls -la ~/practice/
  4. Установить права 644 на файл и 755 на каталог
  5. Создать симлинк link.txt на file.txt
  6. Проверить размер директории: du -sh ~/practice
