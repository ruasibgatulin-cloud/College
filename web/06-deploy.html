6Публикация сайта в интернете

Сделать сайт — половина дела. Вторая половина — выложить его в интернет, чтобы у вас была ссылка, которую можно отправить друзьям, преподавателю или работодателю.

Что даёт публикация
  • Ссылка на сайт — можно отправить кому угодно
  • Портфолио — реальное доказательство навыков
  • Резюме — работодатель откроет и увидит
  • Практика — понять, как работает хостинг и домены
  • Бесплатно — все современные сервисы дают базовый план без оплаты

Домен — адрес сайта, который вводит пользователь.

ЗонаЗначениеСтоимость

Для учёбы можно бесплатно
Домен не обязателен для старта. GitHub Pages, Netlify и Vercel дают бесплатный поддомен:
username.github.io, my-site.netlify.app, my-site.vercel.app

Такой адрес вполне подходит для портфолио и презентаций. Свой домен — когда проект станет важным.

6.3. Способ 1. GitHub Pages

Самый популярный бесплатный хостинг для статических сайтов. Подходит для HTML/CSS/JS без сервера.

Пошаговая инструкция

  1. Создайте аккаунт на github.com.
  2. Создайте репозиторий:
    • Нажмите New repository.
    • Имя: username.github.io, где username — ваш ник на GitHub.
    • Тип: Public.
    • Нажмите Create.
  3. Загрузите файлы:
    • Откройте репозиторий.
    • Add file → Upload files.
    • Перетащите index.html, style.css, script.js, папку с картинками.
    • Commit changes.
  4. Готово! Через 1-2 минуты сайт доступен по адресу: 
    https://username.github.io
Если хотите другой репозиторий
Для проекта с именем portfolio сайт будет доступен по адресу:
https://username.github.io/portfolio/

Настройка: Settings → Pages → Source → main branch.

Как обновлять сайт

Каждый раз, когда меняете файлы, надо загружать их заново:

  1. Откройте репозиторий.
  2. Нажмите на файл, который изменили.
  3. Карандаш (Edit) → внесите изменения → Commit changes.

Или через Git (см. раздел 6.6).

6.4. Способ 2. Netlify

Самый быстрый способ выложить сайт — за 30 секунд.

  1. Откройте netlify.com.
  2. Зарегистрируйтесь через GitHub или email.
  3. На главной странице найдите раздел Drag and drop your site folder here.
  4. Перетащите папку mysite/ в это поле.
  5. Через 10-20 секунд появится ссылка вида: 
    https://sparkling-cat-123abc.netlify.app
  6. Переименуйте: в настройках сайта → Change site name → получите my-portfolio.netlify.app.

Обновление: снова перетащите папку в окно — сайт обновится.

Плюсы Netlify:

  • Загрузка в один клик.
  • Автоматический HTTPS.
  • Бесплатно до 100 ГБ трафика в месяц.
  • Можно подключить свой домен бесплатно.
  • Формы работают из коробки (без бэкенда).

6.5. Способ 3. Vercel

Аналог Netlify, но чуть мощнее для современных фреймворков (React, Next.js).

  1. Откройте vercel.com.
  2. Войдите через GitHub.
  3. Нажмите Add New → Project.
  4. Загрузите файлы через Import или начните проект с шаблона.
  5. Получите ссылку вида my-project.vercel.app.

Подходит, если в будущем перейдёте на фреймворки.

6.6. Git и командная строка

Для профессиональной работы используют Git — систему контроля версий. Через неё удобнее обновлять сайт.

# Проверить, установлен ли Git
git --version

# Настроить имя и email (один раз)
git config --global user.name "Ваше Имя"
git config --global user.email "email@example.com"

# Инициализировать репозиторий в папке сайта
cd путь/к/папке/mysite
git init

# Добавить все файлы
git add .

# Сделать первый коммит
git commit -m "Первый коммит: сайт"

# Связать с GitHub (URL из вашего репозитория)
git remote add origin https://github.com/username/username.github.io.git

# Отправить на GitHub
git branch -M main
git push -u origin main

Обновление сайта после изменений:

git add .
git commit -m "Обновил дизайн главной"
git push
Три команды — и сайт обновлён. GitHub Pages автоматически подхватит изменения.

6.7. Подключение своего домена

Если купили домен (например, my-portfolio.ru), можно подключить его к GitHub Pages или Netlify.

Для GitHub Pages

  1. В настройках репозитория: Settings → Pages → Custom domain.
  2. Введите ваш домен: my-portfolio.ru.
  3. В панели регистратора домена настройте DNS-записи:
    • A-записи для корневого домена: 185.199.108.153, 185.199.109.153, 185.199.110.153, 185.199.111.153
    • CNAME для www: username.github.io
  4. Включите Enforce HTTPS.
  5. Подождите 1-24 часа — DNS обновится.

Для Netlify

  1. В настройках сайта: Domain settings → Add custom domain.
  2. Введите домен.
  3. Netlify покажет, какие DNS-записи настроить.
  4. Настройте в панели регистратора — обычно это CNAME или A-запись.
  5. HTTPS включится автоматически.

6.8. HTTPS — обязательно

HTTPS — защищённое соединение. Браузер показывает зелёный замок, данные шифруются.

  • Google понижает сайты без HTTPS в поиске.
  • Браузеры предупреждают «Не защищено» — пользователи уходят.
  • Формы и пароли без HTTPS передаются в открытом виде.

Хорошая новость: GitHub Pages, Netlify, Vercel выдают HTTPS-сертификат бесплатно и автоматически. Ничего делать не нужно.

Если нужен свой сертификат — Let's Encrypt выдаёт бесплатно на 90 дней с автообновлением.

6.9. Оптимизация перед публикацией

1. Сжать картинки

Большие картинки — главная причина медленной загрузки.

  • TinyPNG (tinypng.com) — сжимает PNG и JPG на 60-80% без видимой потери качества.
  • Squoosh (squoosh.app) — от Google, можно конвертировать в WebP/AVIF.
  • ImageOptim — приложение для Mac.

2. Минификация CSS и JS

Удаление пробелов, комментариев, переносов строк уменьшает размер файлов на 20-40%.

  • CSS Minifier (cssminifier.com)
  • JSCompress (jscompress.com)
  • Или автоматически — сервисы вроде Netlify делают это сами.

3. Проверить скорость

PageSpeed Insights (pagespeed.web.dev) — Google анализирует сайт и говорит, что улучшить.

4. Оптимизировать загрузку

  • Шрифты подключить через preconnect.
  • Ленивая загрузка картинок: <img loading="lazy">.
  • Скрипты — с defer или async.

6.10. Проверка после публикации

Чек-лист перед тем, как давать ссылку
  • ☐ Сайт открывается по HTTPS (зелёный замок)
  • ☐ Работает на телефоне (откройте на своём)
  • ☐ Все ссылки ведут куда надо
  • ☐ Картинки загружаются
  • ☐ Нет ошибок в консоли (F12)
  • ☐ Формы работают
  • ☐ Favicon отображается во вкладке
  • ☐ Заголовок страницы (<title>) осмысленный
  • ☐ Сайт быстрый (по PageSpeed > 70)

Вопросы для самопроверки

Вопрос 1. Чем хостинг отличается от домена?
Хостинг — это «дом», где живут ваши файлы в интернете. Физически — это сервер (компьютер), который отдаёт файлы посетителям.

Домен — это «адрес дома». То, что вводит пользователь в браузере.

Аналогия:
  • Файлы сайта — вещи в квартире.
  • Хостинг — сама квартира (где живут вещи).
  • Домен — адрес квартиры (как её найти).
Можно иметь хостинг без домена (адрес как у GitHub Pages: username.github.io) и домен без хостинга (тогда он никуда не ведёт). Обычно используют вместе.
Вопрос 2. Что такое HTTPS и зачем он нужен?
HTTPS — защищённая версия HTTP. Все данные между браузером и сервером шифруются.

Что даёт:
  • Защита от перехвата — никто в сети (например, Wi-Fi в кафе) не увидит, что вы вводите.
  • Подтверждение подлинности — сайт именно тот, за кого себя выдаёт.
  • Доверие пользователей — зелёный замок в адресной строке.
  • Google не понижает сайты без HTTPS в поиске.
Что было бы без HTTPS: пароли, номера карт, личные сообщения могли бы перехватить злоумышленники в той же сети. Это критично для любых сайтов с формами.

Раньше: HTTPS был только у банков и крупных сервисов — сертификаты стоили дорого.
Сейчас: Let's Encrypt и автоматические сервисы сделали HTTPS бесплатным. Его можно включить в один клик.

Вопрос 4. Зачем оптимизировать картинки?
Картинки — самая тяжёлая часть сайта. Одна фотография может весить больше, чем вся остальная страница вместе.

Пример:
  • Фото с телефона: 5 МБ
  • HTML + CSS + JS: 100 КБ
  • Итого: 5,1 МБ — сайт грузится 10+ секунд на медленном интернете
После сжатия:
  • Фото: 300 КБ (TinyPNG)
  • HTML + CSS + JS: 100 КБ
  • Итого: 400 КБ — сайт грузится 1-2 секунды
Что теряется: почти ничего. 90% качества достаточно для веба.

Правила:
  • Загружать сжатые картинки (JPG/WebP, не PNG для фото).
  • Указывать правильный размер (не 4000px, если показывается в 400px).
  • Использовать loading="lazy" для картинок ниже первого экрана.
