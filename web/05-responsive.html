5Адаптивность и мобильная вёрстка

Больше половины пользователей заходят с телефона. Если сайт не адаптирован — люди уходят. Адаптивность — это умение сайта выглядеть хорошо на любом экране: от 320px (старый iPhone) до 4K-монитора.

Цифры, которые важно знать
  • ~60% мирового веб-трафика — мобильные устройства
  • 53% пользователей уходят, если сайт грузится дольше 3 секунд
  • Google ранжирует мобильную версию сайта первой (mobile-first indexing)
  • Если сайт не адаптирован — Google понижает его в поиске

5.1. Метатег viewport

Без этой строки в <head> телефон покажет сайт как на десктопе — маленьким, с горизонтальной прокруткой.

<meta name="viewport" content="width=device-width, initial-scale=1.0">
width=device-width — ширина страницы = ширина экрана устройства.
initial-scale=1.0 — начальный масштаб 100%.
С метатегом viewport сайт подстраивается под ширину устройства.

5.2. Media queries

Media query — блок CSS, который применяется только при определённых условиях (например, при ширине экрана меньше 768px).

/* Стили для экранов до 768px (мобильные и планшеты) */
@media (max-width: 768px) {
  body { font-size: 14px; }
  .sidebar { display: none; }
  .cards { grid-template-columns: 1fr; }
}

/* Только для десктопов */
@media (min-width: 1024px) {
  body { font-size: 18px; }
  .cards { grid-template-columns: repeat(3, 1fr); }
}

/* Комбинировать */
@media (min-width: 768px) and (max-width: 1024px) {
  /* планшеты */
}

/* Другие условия */
@media print { /* для печати */ }
@media (orientation: portrait) { /* вертикальная ориентация */ }
@media (prefers-color-scheme: dark) { /* тёмная тема системы */ }

Breakpoint — ширина экрана, на которой раскладка меняется.

Не гонитесь за десятками breakpoints. Обычно 3-4 достаточно: мобильный, планшет, десктоп, широкий монитор.

5.4. Mobile-first vs Desktop-first

Два подхода к написанию CSS с media queries.

ПодходКак работаетЧто используется
Mobile-firstСначала стили для мобильного, потом усложняем для больших экрановmin-width
Desktop-firstСначала для десктопа, потом упрощаем для мобильныхmax-width

Современный стандарт — mobile-first. Причины:

  • Мобильных пользователей больше.
  • Легче оптимизировать — начинаем с минимума.
  • Google рекомендует (mobile-first indexing).
  • Меньше «лишнего» CSS загружается на мобильном.
/* Mobile-first подход */

/* Базовые стили — для мобильного */
.container {
  padding: 16px;
}

.cards {
  display: grid;
  grid-template-columns: 1fr;    /* 1 колонка */
  gap: 16px;
}

/* Планшет и больше */
@media (min-width: 768px) {
  .container { padding: 32px; }
  .cards { grid-template-columns: repeat(2, 1fr); }  /* 2 колонки */
}

/* Десктоп */
@media (min-width: 1024px) {
  .cards { grid-template-columns: repeat(3, 1fr); }  /* 3 колонки */
}
Базовые стили — мобильные. Потом «повышаем» для больших экранов.

5.6. Функция clamp() — адаптивные размеры

clamp(мин, предпочтительно, макс) — размер, который плавно меняется между минимумом и максимумом.

/* Размер шрифта плавно меняется */
h1 {
  font-size: clamp(24px, 5vw, 48px);
  /* на узком экране — 24px, на широком — до 48px */
}

/* Отступы */
section {
  padding: clamp(20px, 5vw, 60px) clamp(16px, 3vw, 40px);
}

/* Ширина блока */
.container {
  width: clamp(280px, 90%, 1100px);
  /* минимум 280, максимум 1100, обычно 90% */
}
Одна строчка заменяет media queries для шрифтов и отступов.

5.7. Адаптивные изображения

/* Базовая адаптивность */
img {
  max-width: 100%;
  height: auto;
  display: block;
}

/* object-fit — как вписывается в контейнер */
.card-img {
  width: 100%;
  height: 200px;
  object-fit: cover;   /* обрезать, сохранив пропорции */
  /* contain — вписать целиком */
  /* fill — растянуть (по умолчанию) */
}

/* Тег picture — разные картинки для разных экранов */
<picture>
  <source media="(max-width: 600px)" srcset="small.jpg">
  <source media="(max-width: 1200px)" srcset="medium.jpg">
  <img src="large.jpg" alt="Описание">
</picture>

/* srcset — выбрать картинку по разрешению */
<img src="photo.jpg"
     srcset="photo-400.jpg 400w,
             photo-800.jpg 800w,
             photo-1600.jpg 1600w"
     sizes="(max-width: 600px) 100vw, 50vw"
     alt="Фото">

5.8. Бургер-меню

Самая частая задача в адаптивной вёрстке: на десктопе — обычное меню, на мобильном — кнопка с выпадающим списком.

<!-- HTML -->
<header>
  <div class="logo">Мой сайт</div>
  <button class="burger" aria-label="Меню">☰</button>
  <nav class="menu">
    <ul>
      <li><a href="#">Главная</a></li>
      <li><a href="#">О нас</a></li>
      <li><a href="#">Контакты</a></li>
    </ul>
  </nav>
</header>

<!-- CSS -->
<style>
header {
  display: flex;
  justify-content: space-between;
  align-items: center;
  padding: 16px 20px;
  background: #fff;
  position: relative;
}

.burger {
  display: none;      /* скрыт на десктопе */
  font-size: 24px;
  background: none;
  border: none;
  cursor: pointer;
}

.menu ul {
  display: flex;
  gap: 20px;
  list-style: none;
}

/* На мобильных */
@media (max-width: 640px) {
  .burger { display: block; }

  .menu {
    display: none;
    position: absolute;
    top: 100%;
    left: 0;
    right: 0;
    background: #fff;
    border-top: 1px solid #eee;
  }

  .menu.open { display: block; }

  .menu ul {
    flex-direction: column;
    padding: 20px;
    gap: 12px;
  }
}
</style>

<!-- JS -->
<script>
const burger = document.querySelector('.burger');
const menu = document.querySelector('.menu');

burger.addEventListener('click', () => {
  menu.classList.toggle('open');
  burger.textContent = menu.classList.contains('open') ? '✕' : '☰';
});
</script>
Такой шаблон подходит для 90% сайтов.

5.9. Проверка адаптивности

Как проверить сайт на разных экранах
  1. DevTools (F12): нажмите Ctrl+Shift+M — включится режим устройства.
  2. Выберите устройство: iPhone, iPad, Galaxy и т.д. — или задайте свою ширину.
  3. Покрутите ползунок: меняйте ширину и смотрите, где ломается.
  4. Проверьте ключевые точки: 320, 375, 414, 768, 1024, 1440, 1920.
  5. Реальное устройство: откройте сайт на своём телефоне.
  6. Сервис: responsinator.com, ami.responsivedesign.is

5.11. Практические работы

🎯 ПР №1 · Адаптировать готовый сайт 40 мин
Задача: взять свой сайт и сделать его адаптивным.
  1. Добавьте <meta name="viewport">, если ещё нет.
  2. Проверьте сайт в DevTools (F12 → Ctrl+Shift+M).
  3. Найдите проблемы:
    • Горизонтальная прокрутка?
    • Текст мелкий?
    • Карточки в один столбец на мобильном — читаются?
  4. Добавьте media queries: 
    @media (max-width: 768px) {
  /* мобильные стили */
}
  5. Проверьте на 320, 375, 768, 1024 px.
🎯 ПР №2 · Бургер-меню 40 мин
Задача: сделать бургер-меню по шаблону выше.
  1. Скопируйте HTML/CSS/JS шаблон.
  2. Адаптируйте под свой сайт: цвета, шрифты, логотип.
  3. Проверьте:
    • На десктопе — обычное горизонтальное меню.
    • На мобильном — кнопка ☰.
    • Клик по кнопке — меню раскрывается.
    • Повторный клик — скрывается.
    • Значок меняется на ✕.
🎯 ПР №3 · Адаптивная галерея 30 мин
Задача: сделать галерею с разными картинками для разных экранов.
  1. Возьмите 3 картинки: маленькую (400px), среднюю (800px), большую (1600px).
  2. Используйте тег <picture>: 
    <picture>
  <source media="(max-width: 600px)" srcset="small.jpg">
  <source media="(max-width: 1200px)" srcset="medium.jpg">
  <img src="large.jpg" alt="Фото">
</picture>
  3. Проверьте в DevTools: при сужении окна загружается другая картинка (видно в Network).
🎯 ПР №4 · Типографика с clamp() 30 мин
Задача: сделать шрифты, которые плавно масштабируются.
  1. Замените фиксированные размеры на clamp(): 
    h1 { font-size: clamp(28px, 5vw, 56px); }
h2 { font-size: clamp(22px, 3vw, 36px); }
p  { font-size: clamp(14px, 1.5vw, 18px); }
  2. Проверьте: на телефоне мелкий, на десктопе крупный, переход плавный.
  3. Уберите media queries для шрифтов — они больше не нужны.
🎯 ПР №5 · Полный адаптив 50 мин
Задача: сделать сайт, который отлично смотрится на 5 размерах экрана.
  1. Проверьте сайт на: 320, 375, 768, 1024, 1440 px.
  2. На каждом размере:
    • Нет горизонтальной прокрутки.
    • Текст читается (не слишком мелкий).
    • Кнопки удобно нажимать (44×44 минимум).
    • Меню работает (бургер на мобильном).
    • Карточки перестраиваются.
  3. Сделайте скриншоты каждого размера.
  4. Сдайте отчёт: скриншоты + описание, что исправляли.

Вопросы для самопроверки

Вопрос 1. Зачем нужен метатег viewport?
Без него мобильные браузеры показывают сайт как на десктопе, но уменьшенным. Пользователь видит мелкий текст и вынужден постоянно зумить.

Что делает метатег:
  • Указывает браузеру, что ширина страницы = ширина экрана устройства.
  • Начальный масштаб 100% — без автоматического зума.
  • Это основа адаптивности — без него media queries не сработают правильно.
Правило: всегда добавляйте в <head> при создании новой страницы.
Вопрос 2. Почему mobile-first лучше desktop-first?
Три причины:
  1. Большинство пользователей — мобильные. Логично начинать с того, что важнее.
  2. Меньше CSS на мобильном. Браузер загружает только базовые стили + несколько media queries. При desktop-first мобильные стили «отменяют» десктопные — это лишний код.
  3. Проще усложнять, чем упрощать. Добавить колонки для широкого экрана легче, чем «отменять» их для узкого.
Пример: карточки.
  • Mobile-first: сначала 1 колонка, потом добавляем 2 на планшете, 3 на десктопе.
  • Desktop-first: сначала 3 колонки, потом отменяем до 2, до 1. Больше кода и путаницы.
Вопрос 3. Что такое object-fit и зачем он нужен?
object-fit — свойство, которое определяет, как изображение вписывается в свой контейнер.

Проблема: если задать картинке фиксированные width и height, она искажается — теряет пропорции.

Решения:
  • object-fit: cover — картинка заполняет контейнер, обрезая лишнее. Пропорции сохраняются.
  • object-fit: contain — картинка вписывается целиком, по краям остаётся пустое место.
  • object-fit: fill — растягивается (по умолчанию, искажается).
  • object-fit: none — картинка в исходном размере.
Где применяется: галереи, карточки товаров, аватары, обложки статей — где нужно, чтобы все картинки были одного размера.
Вопрос 4. Как проверить адаптивность без телефона?
Основной способ — DevTools:
  1. F12 — открыть инструменты разработчика.
  2. Ctrl+Shift+M — переключить в режим устройства.
  3. В верхней панели выбрать модель (iPhone, iPad, Galaxy) или задать свои размеры.
  4. Менять размеры и смотреть, где ломается вёрстка.
Совет: проверьте «крайние» размеры: 320px (старый iPhone), 768px (планшет), 1920px (большой монитор). Часто проблемы только на границах.

Онлайн-сервисы: responsinator.com, ami.responsivedesign.is — показывают сайт в разных разрешениях.

Но: реальный телефон всё равно лучше. DevTools не всегда показывает, как работают касания, скролл, зум. Если есть возможность — проверьте на живом устройстве.
